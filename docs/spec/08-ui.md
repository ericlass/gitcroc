# 8. UI specification

The window has a tab bar with one tab per open workspace, a toolbar and three resizable panes: the tree on the left, history in the middle, changes on the right. What is selected in one pane decides what the next pane to its right shows.

```text
+-----------------------------------------------------------------------------+
| Tabs: one per workspace                                              [+]    |
+-----------------------------------------------------------------------------+
| Toolbar: Fetch, Pull, Push, Branch, Merge, Stash, command palette, Settings |
+----------------------+---------------------------+--------------------------+
| Tree            ---> | History              ---> | Changes                  |
|                      |                           |                          |
| Backend . mixed (2)  | Uncommitted changes (3)   | Commit header and        |
|   Branches           | ------------------------- | message                  |
|   api . main         | > Fix token refresh       |                          |
| > auth . feature/x   |   Merge feature/x         | Changed files            |
|     branches, tags,  |   Add retry to client     | (flat list or folder     |
|     stashes          |                           | tree)                    |
| Frontend . main      |                           |                          |
| Ungrouped            | repo or branch selected:  | Diff of the selected     |
|                      |   commit graph            | file: inline or          |
|                      | group selected:           | side-by-side; conflict   |
| groups, repos,       |   merged list by date     | editor replaces it in    |
| branches             |                           | conflict state           |
+----------------------+---------------------------+--------------------------+
| Status bar: running jobs, progress, result reports                          |
+-----------------------------------------------------------------------------+
```

The highlighted repo in the tree decides the history list, and the highlighted commit decides the changes pane.

## Workspace tabs

- **UI-27** One tab is one workspace. Several workspaces can be open at once, for example a Java project and a C# project. A workspace can be open in only one tab; opening it again switches to that tab.
- **UI-28** The tab bar has a "+" button that lists existing workspaces and offers New workspace and Import workspace. Tabs can be reordered by dragging and closed. Closing a tab does not delete the workspace.
- **UI-29** Each tab keeps its own tree selection, expanded nodes, scroll positions, pane sizes, filter text and unsaved conflict editor state (OPS-9). Switching tabs restores them exactly.
- **UI-30** Jobs keep running when their tab is in the background. A background tab is not watched and not refreshed (PERF-6, OPS-7 apply to the active tab only); it refreshes when it becomes active. After a job ends in a background tab, only the repos that job touched are re-read.
- **UI-31** A background tab releases its loaded history pages and diffs and keeps only repo summaries, so memory grows with the active tab, not with the number of tabs.
- **UI-32** A tab shows a badge while it has running jobs, and a marker when a job in it ended with a *failed* or *conflict* outcome that the user has not yet seen.
- **UI-33** Open tabs, their order and the active tab are restored on restart. Switching tabs MUST meet the "switch selection" budget in section 9 for first paint.

## Tree pane (left)

- **UI-1** Structure, top to bottom: one node per group in user order, then Ungrouped. A group contains a **Branches** node and its repos. A repo contains **Local**, **Remotes**, **Tags** and **Stashes**. Branch names containing `/` fold into folders.
- **UI-2** A repo that belongs to several groups appears under each of them. It is the same repo; selecting either shows the same thing.
- **UI-3** A repo row shows: name, current branch, ahead and behind counts, a dot when the working copy is dirty, a conflict icon in conflict state, a spinner while a job runs, and a warning icon when the path is missing.
- **UI-4** A group row shows: name, member count, the derived branch (GRP-4), and the totals of dirty repos and repos in conflict state.
- **UI-5** A group's **Branches** node lists every local branch name that exists in at least one member, with a count such as `feature/x (3/5)`. Double-click starts a group checkout of that name.
- **UI-6** Selection is single, except that repo rows can be multi-selected with Ctrl/Cmd-click and Shift-click to form a target set (GRP-5). Branch, tag and stash rows are never multi-selected.
- **UI-7** Double-click on a local branch checks it out. Every row has a context menu with the operations valid for it. Repos can be dragged between groups; holding Ctrl/Alt adds instead of moves.
- **UI-8** A filter box above the tree filters repos and branches by substring as the user types.

## History pane (middle)

| Tree selection | History shows |
| --- | --- |
| Repo | Commit graph of all local and remote branches, newest first |
| Branch, tag or remote branch | Commit graph reachable from that ref only |
| Stash | The stash as a single commit row |
| Group, or several repos | One merged list of commits reachable from each repo's current HEAD, newest first by commit date, with a repo column and no graph lines |

- **UI-9** Columns: graph, subject with ref labels, author, date, short hash. In the merged list the graph column is replaced by the repo name.
- **UI-10** For a single repo with a dirty working copy, the first row is "Uncommitted changes (n)". In conflict state the banner of OPS-2 sits above the list.
- **UI-11** For a group or multi-selection, a summary strip above the list has one line per repo: branch, ahead and behind, dirty count, conflict flag. Clicking a line selects that repo in the tree.
- **UI-12** A search box filters by subject, author or hash prefix. Filtering runs in the core, not in the UI.
- **UI-13** Context menu on a commit: checkout, create branch here, create tag here, cherry-pick, revert, reset current branch to here, copy hash. Cherry-pick accepts a multi-selection of commits from one repo.

## Changes pane (right)

- **UI-14** For a commit: header (full hash, author, date, full message, parents), then the changed files as a flat list or a folder tree (toggle), then the diff of the selected file.
- **UI-15** For "Uncommitted changes": two file lists, Staged and Unstaged (untracked files are in Unstaged), the diff of the selected file with stage, unstage and discard controls per hunk, and the commit message box with Commit and Amend.
- **UI-16** For a merge commit the diff is against the first parent, with a selector to switch parent.
- **UI-17** The diff has two modes, inline and side-by-side, toggled in the pane header and remembered globally. Options: ignore whitespace, wrap lines, context lines (3, 10, whole file).
- **UI-18** Binary files show "binary file changed" with sizes; images show before and after. A diff over 20,000 changed lines is collapsed until the user clicks "Load diff".
- **UI-19** The pane can be docked right (default) or bottom. The choice is remembered per workspace.

* **UI-34** For a group or multi-selection with at least one dirty repo, the first row of the merged list is "Uncommitted changes (n repos)". Selecting it shows UI-15 with the Staged and Unstaged lists sectioned by repo, and one commit message box. Its Commit button runs the group Commit of section 5 and is labelled with the number of repos that have staged changes. Amend is not offered here.

## Toolbar, jobs and settings

- **UI-20** Toolbar: Fetch, Pull, Push, Branch, Merge, Stash acting on the current target set, then a command palette trigger and Settings. Buttons that cannot apply to the current selection are disabled, not hidden.
- **UI-21** A status bar shows running jobs with progress. Clicking it opens the job list, which covers all tabs and labels each job with its workspace, and where each job's result report (GRP-7) and raw git output stay available until the app closes.
- **UI-22** The command palette (Ctrl/Cmd+K) lists every operation and every repo, group and branch for keyboard navigation. Every operation in sections 5 and 6 MUST be reachable without a mouse.

## Themes

- **UI-23** App theme: light, dark, or follow the system (default). Implemented as CSS variables only; no component hardcodes a color.
- **UI-24** Code themes apply to diffs and the conflict editor and are independent of the app theme. The user picks one code theme for light mode and one for dark mode. v1 ships at least 8: GitHub Light, GitHub Dark, Solarized Light, Solarized Dark, One Dark, Dracula, Nord, Monokai.
- **UI-25** Added, removed and conflict colors come from the code theme and MUST keep a contrast ratio of at least 4.5:1 against the text on them.
- **UI-26** UI font and code font, with sizes, are settings. Defaults are the system UI font and the system monospace font.
