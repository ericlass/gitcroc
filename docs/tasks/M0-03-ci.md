# M0-03 Continuous integration

## Goal
Every pull request is checked by `just check` on Windows, macOS and Linux, and cannot merge unless all three pass.

## Depends on
M0-02

## Spec
Implements: QA-1 (Rust half; M0-04 adds the front-end half)
No test needed: QA-1 (the workflow itself is the proof)
Respects: D6, D13, QA-5

## In scope
- `.github/workflows/ci.yml`, triggered on pull requests and on pushes to `main`.
- Matrix: `ubuntu-22.04` (gives glibc 2.35, the D6 floor), `windows-latest`, `macos-latest` (Apple silicon).
- Steps: checkout, install the pinned Rust toolchain, install `just` and `cargo-deny`, cache cargo registry and `target`, run `just check`.
- The workflow calls only `just check`, never individual commands, so local and CI checks cannot drift (QA-5).
- First step on every runner prints `git --version` and fails if it is older than 2.40 (D13). Later tasks' integration tests rely on it.
- Concurrency group that cancels superseded runs of the same branch.
- `README.md` at the repo root: one paragraph on what gitcroc is, the CI status badge, the MIT license line, and a pointer to `docs/spec/`.
- Document in `CONTRIBUTING.md` that the three CI jobs must be set as required checks in the repository's branch protection (a manual step for the repository owner).

## Out of scope
- Building installers or uploading artifacts (M0-08).
- Nightly benchmark job (M1).
- Linux system packages for WebKitGTK; M0-04 adds them when Tauri arrives.

## Acceptance
- A pull request with a deliberately failing test shows three red jobs; reverting it shows three green jobs.
- Total CI time for a cached run is under 10 minutes per platform; note the measured times in the pull request.
